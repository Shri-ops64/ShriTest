Change Notices · RFI form variant

  • Same register, different modal. The Raise New modal switches between PCN and RFI form schemas via the toggle at the top. The register table behind it is identical.
  • Document upload still primary. RFIs typically reference a drawing or spec excerpt. The uploaded PDF here is a marked-up mechanical drawing.
  • No cost/hours/schedule impact fields on RFI submission. An RFI by itself doesn't carry impact. The answer might, and that gets logged when the RFI is marked Answered (see Detail view spec).
  • "Send to" is required. Unlike PCN which goes through internal sign-off, an RFI must have an explicit recipient.
  • Discipline tagging (Plumbing / HVAC / Electrical / etc) helps with filtering and routing. Single-select.
  • Priority field (Standard / Urgent / Critical) helps surface what's blocking work. Urgent and Critical would render with amber/red treatment in the register.
  • Drawing reference and Spec section are optional but common in formal RFIs. Free-text fields so they can carry any identifier the project uses.
  • "Blocking task?" toggle is a clever bridge: if Yes, raising this RFI automatically marks the linked task as Blocked with the RFI as the blocker reason. When the RFI is answered, the task can be auto-unblocked. Worth validating with Justin.

Field set (subject to client feedback)

  • RFI conventions are similar to PCN: industry-standard defaults that need real-world validation.
