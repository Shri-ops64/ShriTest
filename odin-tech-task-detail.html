Task detail notes

  • Lands here from tapping a task row on the per-project view's My Open Tasks section, or the full task list.
  • Status pill above the title shows current state with colored dot.
  • Description shows the task description authored by admin. Read-only for the tech.
  • Details meta-pairs show due date (highlighted amber when within 3 days), assignee, hours logged, start date. Compact and scannable.
  • Two big status-change action buttons: Mark Complete (green) and Mark Blocked (red). Side-by-side. These are the only state changes the tech can perform (plus implicit "started" when they first log time against the task).
  • Tapping Mark Blocked opens a small modal asking for the blocking reason (required text field). The reason then surfaces in the admin web Tasks view and on this screen until the tech unblocks the task.
  • Tapping Mark Complete immediately transitions to Complete with confirmation. Emits a Task Event to the admin Activity feed.
  • My Activity on This Task section shows the tech's own history with this task: hours logged via daily logs, status changes they made. Helps the tech reconstruct what they did on this task without scrolling the project-wide activity.

What's intentionally NOT here

  • No edit-description capability (admin owns task content)
  • No assign-to-someone-else (admin reassigns)
  • No comment thread on the task (lower-priority noise; admin-side Activity handles cross-team discussion)
  • No "delete task" affordance (admin only)

Blocked state variant

  • If the task is currently Blocked, the page shows a red-tinted "Blocked" banner at the top of the body with the reason and timestamp.
  • The action buttons change: "Mark Complete" stays, and "Mark Blocked" is replaced with "Unblock" (resumes In Progress state).
