RFI detail panel notes (June 2 simplification)

  • Two states shown, not three. Per Justin's June 2 direction: RFI submission no longer has an approval workflow. RFIs go straight to log on submission. The previous DRAFT → OPEN gate is gone. State 1 is Open (awaiting GC reply), State 2 is Closed (PM has captured the reply and resolved the RFI). Both are the same panel; content changes based on status.
  • Email to GC happens OUTSIDE Odin. Justin's team has an existing email process they prefer to keep using. The compose-and-send flow that was in the previous spec has been removed: no in-Odin composer, no PDF generation, no Outlook hand-off, no "Send to GC" button. PM emails Brett directly from their normal email client.
  • Odin's role is storage and tracking. The question, attachments, photos, and eventual response live in Odin so the team has a single record. PM emails the question to the GC from their own email client, and captures the response back in Odin once it arrives.
  • Mark Answered opens a capture modal. Clicking "Mark Answered" on an Open RFI opens the "Capture GC response" modal: a paste box for the response text, a "Response from" field (sender name + org), and a "Date received" field. On Save, the status flips to Answered and the pasted text renders in the purple-tinted Response box attributed to the sender and timestamp. This is the explicit answer-capture step (the response is never auto-pulled; the PM enters it).
  • Close RFI is the primary action on Answered RFIs; "Create PCN from this RFI" sits beside it (D-038). No outcome radio inside the panel. The branch is explicit: a pure clarification gets closed; a change to cost or hours always becomes a PCN, so "Create PCN from this RFI" opens the PCN ingest pre-filled with the RFI link and the response as the description (carrying any potential-cost-impact notes forward). The "Associated RFI" field on the PCN intake captures the back-link. In the worked example the GC confirmed no cost impact, so the path resolves to Close.
  • Potential cost impact is informal notes only (D-038). A field user or the PM can jot likely cost/hours impact while the RFI is open (the amber section). It deliberately does not hold formal cost lines: costs and hours are formalized on the PCN, per Thor's rule that any cost or hours change becomes a PCN. The notes seed the PCN if one is raised; otherwise the RFI just closes. This is the reframed version of the "additional costs tab" the client review asked for.
  • No Download button on the panel. Removed to keep the panel lean (Jun 9). The individual attachment rows keep their own download icon for pulling a specific file; there is no whole-RFI bundle export in v1. Can revisit in v1.1 if a packaged export is wanted.
  • Email notification to PM on RFI submission. When a tech submits an RFI from mobile, the PM gets a notification email automatically. (Backend hook, no UI surface in Odin beyond a "PM notified" confirmation toast on the tech side.)

What was removed from the prior spec

  • DRAFT state and PM approval gate. Cut. RFIs submitted by techs go straight to OPEN.
  • Compose-and-send panel. Cut entirely. No PDF generation, no Outlook mailto, no "Send to GC" button.
  • Whole-RFI Download / bundle export. Cut (Jun 9). Per-attachment download stays; no packaged question+response export in v1.
  • SENT status in the RFI state machine. Cut. Status flow is now: OPEN → ANSWERED → CLOSED (with optional skip to CLOSED if no answer is needed).
  • Outcome radio on the Answered state. Cut. PCN creation happens separately on the Change Notices tab when warranted.
  • RFI_DRAFT_CREATED, RFI_DRAFT_APPROVED, RFI_SENT, RFI_OUTCOME_DECIDED activity events. Cut from the event enum.

Data model adjustments

  • RFI state enum simplified: OPEN → ANSWERED → CLOSED. (Was: DRAFT → OPEN → SENT → ANSWERED → CLOSED.)
  • Fields removed from Change Notice (RFI specifics): formal_body, pdf_storage_path, cc_recipients, sent_at, sent_to, sent_by_user_id.
  • Fields retained: question (the casual description), attachments, response_text, response_captured_at, response_captured_by_user_id, linked_task_id, raised_by_user_id, raised_at.
  • Activity events retained: RFI_CREATED (raised from mobile or admin), RFI_ANSWERED, RFI_CLOSED.
