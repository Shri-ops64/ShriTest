Daily Log composer notes

  • Project context is pre-filled and shown as a pill at the top, not editable in this view. Tech came here from the per-project view, so the project is already chosen. To switch projects, they back out.
  • Date is auto-filled to today. v1.1 could allow back-dating for "I forgot to submit yesterday's log." For now: today only.
  • Photos section is the top of the form, not the bottom. This is intentional. Techs primarily care about photo capture; the form is built around that, not as an afterthought.
  • Two large photo capture buttons: "Take Photo" (primary black, opens camera) and "From Library" (secondary, opens photo picker). Side-by-side, both prominent.
  • Photo thumbnails appear below the buttons in a 4-column grid. Each thumb has a remove (X) badge in the corner. Tapping a thumb opens it full-size with an option to add a caption (out of scope for this mockup but specced).
  • Photos auto-tagged to this log AND auto-routed to the project's Site Photos folder. When the log is submitted, photos live in both places (linked to the log, and findable via the project's DAM).
  • Summary textarea is required with a character counter (2000 max). Placeholder text gives examples of what to write.
  • Hours stepper uses big +/- buttons in a 0.5 hr increment, plus quick-pick shortcut chips below (4, 6, 6.5, 8, 10, Custom). The shortcut "6.5" is highlighted to show the current selection.
  • Tasks worked on is optional. Shows the tech's open tasks on this project with checkboxes. Tap to link the log to those tasks. The "Blocked" task is shown with a red label so the tech can see it but knows it's currently in a blocked state.
  • Draft auto-save indicator at top right shows "Draft saved" in amber after any field change. If tech navigates away mid-composing, the draft persists.
  • Two footer actions: "Save Draft" (secondary outline, stays in draft, won't notify admin) and "Submit Log" (primary, pink-red gradient matching the production Sign Off pattern). Submitting moves the log to "submitted" state and admin sees it for review.

What's intentionally NOT here

  • No location field. GPS auto-captured silently if device permits, not shown in the form.
  • No materials used field (could be v1.1).
  • No weather conditions (Daryl had this; unnecessary).
  • No mascot character. No lime green.
  • No "submit for approval" since admin review happens passively (admin marks Reviewed on the web side).
