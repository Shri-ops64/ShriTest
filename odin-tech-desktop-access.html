Tech access on desktop
When a tech logs into Odin on desktop and accesses project surfaces, they see the same screens as admin users. Differences are action-level only (permissions on what they can edit, delete, or approve). This page documents the access model in one place so the existing admin mockups can serve both audiences without duplicate designs.
Architectural decision
One Project Module, role-scoped at the action layer. The split admin and tech interfaces elsewhere in Odin are a legacy architecture constraint we are not extending. The Project Module is a single set of screens; what a user can do on those screens is determined by their role, not by which interface they entered through. Per Justin: no information hiding for techs. They see everything; they just cannot edit what is not theirs.

Per-surface access model
odin-projects-list.html
Projects list
Landing screen when tech clicks "Projects" in top nav
Same screen as admin sees, filtered to projects this tech is assigned to. Status column, code column, dates, PM column, search and filter chips all visible. Cancelled and Complete projects visible if the tech was assigned to them. Empty state if no assignments yet.

Tech CAN

  • Search and filter the list
  • Open any project they are assigned to
  • Sort by any column

Tech CANNOT

  • Click the "New Project" button (hidden for tech role)
  • Open projects they are not assigned to
  • Use bulk actions if any are added later
odin-overview-current-brand.html
Overview tab
Default tab when entering a project
Same screen as admin, all widgets visible per Justin's direction. Header Days Left pill + Foreman/Supervisor health chips, Milestones + Recent Activity in row 1, secondary KPI counts strip, then Latest Project Logs + Team + External Contacts in row 3. The "Edit Project" button in the header is hidden for tech.

Tech CAN

  • View all widgets on the Overview tab
  • See the Days Left pill in the project header
  • View milestones with target dates and completion state
  • Read the Recent Activity feed (full project feed, no filtering)
  • See the counts strip (Active Tasks, Open Blockers, Open RFIs, Project Logs This Week)
  • Click activity preview rows to expand or jump to the Activity tab

Tech CANNOT

  • See or click the "Edit Project" header button
  • Edit milestones (read-only checkboxes)
  • Add or remove team members
  • Manage External Contacts entries
odin-tasks.html
Tasks tab
Labor budgeting and tracking
Same screen as admin. Tech sees the project estimate strip, Original Scope cluster, Approved PCN clusters, est-vs-act bars per task, and the Draft Tasks review inbox (filtered to drafts this tech created). All tasks visible regardless of assignment.

Tech CAN

  • View all tasks and the project labor estimate
  • See est-vs-act bars at task, cluster, and project levels
  • Open their own drafts in the Draft Tasks inbox
  • Mark their assigned tasks as In Progress, Blocked, or Done

Tech CANNOT

  • Approve or reject drafts (PM-only action)
  • See other techs' drafts in the inbox (filtered)
  • Edit task estimates or due dates on tasks they do not own
  • Cancel tasks (PM-only action)
odin-time.html
Time tab
Project-scoped timesheet log
Same screen as admin. Per Justin's direction, no information hiding. Tech sees the full team's entries on this project, the overview cards (this week, last week, this month, last month) summing the whole project, and the filtered summary.

Tech CAN

  • View all entries on this project, including other techs'
  • See the Project-to-date overview cards
  • Filter by date, type, employee, department, task, status
  • Edit or delete their own entries (Actions column)
  • Export entries (CSV)

Tech CANNOT

  • Edit or delete other techs' entries
  • Approve entries from Pending → Approved (admin action)
  • Use Export Payroll (admin-only, exposes pay calculations)
odin-project-logs.html
Project Logs tab
Tech logs + Foreman reports + Supervisor reports
Same screen as admin. Tech sees the unified Project Logs surface with sub-tabs filtering by log type. Tech logs and foreman reports are fully visible; supervisor reports show with two fields restricted (Foreman Performance, Verification of Foreman Report accuracy) per D-026.

Tech CAN

  • View all tech daily logs on this project
  • View all foreman weekly reports
  • View supervisor reports with the two confidential fields omitted
  • Open any log to read the full submission on the detail page
  • Edit or delete their own logs

Tech CANNOT

  • Compose Foreman or Supervisor Reports (project-role gated per D-026)
  • See the Foreman Performance rating on Supervisor Reports
  • See the Verification of Foreman Report field on Supervisor Reports
  • Edit or delete logs they did not author
odin-activity.html
Activity tab
Full project activity feed
Same screen as admin. Full chronological feed of all events on the project: posts, task status changes, time submissions, daily logs, PCN approvals, RFI sends. Per Justin's direction, no dollar-amount filtering; tech sees PCN cost impact figures just as admin does.

Tech CAN

  • View the full activity feed including PCN dollar amounts
  • Compose a new post (text comment, no system events)
  • Filter by event type

Tech CANNOT

  • Edit or delete events they did not create
  • Delete posts authored by other team members
odin-assets-current-brand.html
Assets tab
Project DAM, folders and files
Same screen as admin. Tech sees all folders, all files. Can upload files into folders (technicians submit site photos and documents). Cannot manage folder structure or perform destructive actions.

Tech CAN

  • Browse all folders and files
  • Download files
  • Upload new files into existing folders
  • Tag and describe files they upload

Tech CANNOT

  • Create or rename folders
  • Move files between folders
  • Delete files (move to Trash)
  • Access the Trash view or restore deleted files
odin-change-notices-list.html
Change Notices tab
PCN and RFI register
Same screen as admin per Justin's direction. Tech sees the full register including PCNs (with approved cost impact dollar amounts) and RFIs. Cannot initiate intake of either, but can open existing records to read context.

Tech CAN

  • View the full PCN/RFI register including cost impact
  • Open PCN detail panels to read context
  • Open RFI detail panels to read the question and response
  • Raise an RFI via the mobile composer (already in scope)

Tech CANNOT

  • Ingest a PCN (PM action only)
  • Compose and send an RFI to the GC (PM action only)
  • Approve or reject draft RFIs from techs (PM action only)
  • Close PCNs or RFIs (PM action only)

Surfaces hidden from tech role entirely

Two project surfaces are not visible to tech users on either the navigation or any direct link. Attempting to navigate to them yields a "Not available" message.

Client Reports tab. Generation and management of GC-facing project reports is a PM responsibility; the tech does not interact with this surface.
Edit Project. The Edit Project surface (project basics, dates, team management, external contacts, Project Actions like Cancel) is admin-only. Tech users cannot access the editor.

Implementation notes for Mandeep

  • One set of mockups, role-scoped at render time. The admin mockups in this deck are the canonical visuals. The tech variant is the same component tree with role-conditioned rendering for action buttons and editable controls. No duplicate templates.
  • Permissions live at the action layer, not the view layer. A tech viewing the Tasks tab loads the same query as an admin (all project tasks). The Edit and Approve buttons on rows are conditionally hidden based on currentUser.role and ownership checks.
  • Top-nav placement. Add a "Projects" item to the tech desktop nav between Notes and Admin. Visibility rule: any user with at least one entry in the project assignments table.
  • Default landing on click of Projects nav item: the Projects list filtered to project_assignments WHERE user_id = currentUser.id. Same component as admin, different query scope.
  • Hidden tabs (Client Reports) and hidden actions (Edit Project, Reject Draft, Approve Entry, etc.) render as null on the rendered tab strip and button group respectively. Tech does not see disabled greyed-out controls; they see nothing.
  • Mobile and desktop access models are consistent. What a tech can do on mobile (Submit Time, Write Daily Tech Log, Raise RFI, Mark Task Done) is the same set of actions they can do on desktop. Desktop just gives them the broader read-view of the project alongside.
  • Mandeep's Tech Home V3 dependency. The desktop Tech Home shipped by V3 reserves a "Projects" slot in its bottom row. That slot is populated with a Projects card matching the mobile pattern in odin-tech-home.html. No coordination needed beyond confirming slot width and row layout once V3 lands.
