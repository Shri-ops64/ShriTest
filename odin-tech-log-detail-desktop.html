Section 7.6 · Daily Tech Log detail

Desktop conversionv1

Converted from mobile mockup Built from the mobile Daily Tech Log Detail (read) view, adapted to the established desktop chrome — top nav with the Timesheets dropdown and Projects tab, breadcrumb, and this annotation rail.
Read mode by default This is the read view of a submitted log. "Edit" in the header switches to the composer (the desktop conversion built previously), with all fields populated. Same relationship as on mobile.
Status + timeline moved into the page header Mobile stacks the status pill and submission timeline under the title in the app's title block. On desktop these live in the header row next to the title, with Edit as a clear top-right action — consistent with the per-project view's header pattern.
Hours on Site promoted into the sticky rail Rather than sitting as a card in the main reading column (mobile), the hours readout — with its pink-red gradient icon, matching the Submit Time affordance elsewhere — anchors the sticky right rail alongside a compact log-details card (project, date, submitted by, timestamps). Keeps this always visible while scrolling photos/summary/tasks.
Photos — 5-column grid, hover to preview Widened from mobile's 3-column grid to use the extra desktop width. "Add Photos" (top-right of the card) is the same affordance as the per-project view — it attaches photos to this specific log, not just the project's Site Photos folder. Solves "I forgot to add photos before submitting."
Tasks Worked On — read-only Carried over unchanged: rows show which tasks the tech linked hours to, read-only from this view. Clicking a row could route to task detail in a future pass, but doesn't edit the link here.
Draft state — not shown here Per the mobile spec: when the log is still a Draft, the status pill reads "Draft" (grey) and a primary "Submit Log" button appears in place of Edit-only access. Worth a separate desktop variant once this reviewed-state base is signed off.
