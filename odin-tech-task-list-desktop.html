Section 7.7 · Project Tasks (full list)

Desktop conversionv1

Converted from mobile mockup Built from the mobile Project Tasks list, adapted to the established desktop chrome (nav, breadcrumb, annotation rail) while keeping every content decision from the mobile version intact.
Scoped to "all tasks on this project" Per the June 2 direction: tasks aren't assigned to individuals. They belong to the project, and any staff — including techs not officially on it — can see them and log time. This desktop list shows the same set any tech would see, not a personalized subset.
Search box added for desktop Mobile relies on scrolling through a short list. Desktop adds a search box in the header, since the extra width has room for it and a project can have far more than 7 tasks.
Filter chips + status grouping (unchanged) Open (default: Not Started + In Progress + Blocked) / All / Complete, with counts. Groups render in priority order — Blocked, then In Progress, then Not Started — with Complete tasks appearing only when that filter is active.
Three-dot menu → floating dropdown Mobile opens an inline action sheet below the card because there's no room to float a menu. Desktop replaces this with a standard floating dropdown anchored to the three-dot button — same actions, more standard desktop interaction. Shown open here on "Install main supply line" to demonstrate the Blocked-state menu (Unblock primary, Mark Complete, View linked RFI).
Actions adapt to status (unchanged) Blocked → Unblock (primary), Mark Complete, View linked RFI/PCN. In Progress / Not Started → Mark Complete, Mark Blocked. Complete → Reopen (not shown; only visible under the Complete filter).
Anyone can change task status Per June 2 direction: any staff member can mark a task Complete or Blocked, not just an assignee — there's no "owner" concept on tasks.
No task detail page — still true on desktop tech Editing task name, estimate, due date, or Task ID stays PM territory on the admin side, not this tech surface. These tech actions remain operational only (status changes). A tech who spots a problem needing PM attention raises an RFI instead.
