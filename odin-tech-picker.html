Project picker notes

  • Opens when a tech needs to pick a project: from Submit Timesheet (after picking "Projects" work type), from Write Daily Log (the universal entry path), or from "View all" in the My Projects home widget.
  • Two-section layout. Top: "Assigned to me" (the tech's current projects, same set shown in the home widget). Bottom: "All active projects" (every other project active in Thor's org).
  • Common case is one tap: the tech's usual project sits at the top, they tap, done.
  • Edge case (swing-by visit, emergency call) is a quick scroll or search. No "request access" friction. No "you're not on this project" error.
  • Search field searches across both sections. Tech who knows the project name just types and finds it instantly.
  • Section counts in the headers ("3" and "12") give a sense of scale and confirm the sections are working.
  • No "Not assigned" tag or warning on projects in the second section. Per Justin's open-culture preference, the act of contributing to a project isn't worth flagging visually. The tech contributes, the log is recorded, done.
  • Tap any row proceeds to the next step in the flow (the timesheet form or daily log composer, with the chosen project pre-filled).

Where this picker appears

  • Home → Submit a timesheet → pick "Projects" work type → this picker
  • Home → Hamburger → "All Projects" → this picker as a browser, tap to view per-project tech view
  • Home → My Projects widget → "View all" → this picker
  • Inside a project, tapping "Submit Time" or "Write Daily Log" does NOT open this picker (the project is already chosen)
