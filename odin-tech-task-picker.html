Task picker (bottom sheet, shared component per June 2 direction)

  • One consolidated picker used by Submit Time and the Daily Tech Log composer. Per Justin's June 2 direction: the task selector in both flows should be the same UI. This file is the canonical pattern.
  • Bottom-sheet pattern rather than full-screen takeover. Lets the tech see the parent form's project context in the dimmed background, which reduces "where am I?" confusion when this opens. Sheet takes up about 80% of viewport height, drag-handle at the top for the swipe-to-dismiss gesture.
  • Search at the top is the primary discovery affordance. With potentially hundreds of tasks per project (Jonas cost items), search is essential. Filters the visible list as the tech types.
  • No Mine / All filter chips. Per June 2 direction: tasks are no longer assigned to individuals. They belong to the project and any staff can see and log time against them. Filter chips removed; status grouping in the list provides the structure.
  • Tasks grouped by status: In Progress at top (most likely target), then Blocked (visible but visually discouraged), then Not Started. Complete tasks hidden by default; toggle to show on demand if needed.
  • Selected task gets a blue border and blue-soft background, plus a small filled blue circle with a white checkmark on the right edge. Unambiguous visual feedback.
  • Each task row carries a tiny est-vs-act bar in the meta row (e.g. "2.5 / 4h" with a small fill bar). Lets the tech see at a glance how much budget remains before they log against a task that's already over-estimate.
  • Blocked tasks render with the red status icon and surface the blocking reason inline (e.g. "Blocked by RFI-008"). Tech can still select a blocked task to log time against (work might have happened before the block came in), but the red treatment is a visual flag.

The Other row

  • Sits at the very top of the sheet body, above the status groups, with a dashed-outline icon distinguishing it from real task rows. Followed by an "or pick a task" divider so it visually reads as a separate option, not as the first task in the list.
  • Why it exists. Techs may not know which task they're on, or no suitable task may exist yet. Without an explicit "no task" affordance, an empty Task field reads as "you forgot something" and creates friction. Other turns that into a deliberate, no-judgment choice.
  • Especially important now since techs can no longer create tasks (per June 2). If the tech's work doesn't fit any existing task, Other is the release valve. The PM reviews Other hours and either reassigns them to an existing task or sets up a new Jonas cost item (and a corresponding Odin task) for the work.
  • Behavior on tap. Picker closes, returns to parent form with the Task field showing "Other · General project work" instead of being empty. Time entry or daily log saves with task_id = NULL; the UI label "Other" is rendered from that NULL state for consistency.
  • Hours roll into project totals (Time tab and Overview cards) but not into any specific task's actual hours. Tasks tab est-vs-act bars are unaffected by Other entries.

What was removed from the prior spec (June 2)

  • "Create new task" affordance at the bottom of the picker. Cut. Per Justin: techs cannot create tasks. Tasks correspond to Jonas cost items which are set up by the PM in Jonas at the start of a job.
  • State 2 Create New composer. Cut along with the affordance. The mini-composer for tech-created drafts no longer exists.
  • Draft pill and "Awaiting PM review" treatment. Cut. Tasks no longer have a DRAFT status; all tasks are PM-created and live.
  • Mine / All filter chips. Cut. Tasks are not assigned to individuals; the distinction is meaningless.

Entry points to this picker

  • Submit Time form (odin-tech-time-submit.html): tapping the Task field opens this.
  • Daily Tech Log composer (odin-tech-log-composer.html): tapping the Task field opens this. Same component, same behavior. Per June 2 consolidation direction.
  • RFI composer (odin-tech-rfi-composer.html): tapping the Linked Task field opens this. Same component.

Out of scope

  • Recent tasks pinned at the top regardless of status (parked for v1.1)
  • Multi-select (this is a single-task picker, not a multi-link affordance)
  • Inline status changes on tasks while picking (would create surprising side effects from a picker)
  • Tech-created tasks (cut June 2)
