Section 7.5 · Daily Tech Log composer

Desktop conversionv1

Converted from mobile mockup Built from the mobile Daily Tech Log Composer, adapted to the established desktop chrome: grey top nav with the collapsible Timesheets dropdown and standalone Projects tab, breadcrumb, white page background, and this annotation rail.
Sticky summary rail replaces the mobile footer bar Mobile pins Save Draft / Submit Log to a fixed bottom bar because there's no room elsewhere. Desktop has the width for a second column, so the actions live in a sticky right rail alongside a running summary (project, date, photo count, total hours, allocation status) that stays visible while the tech scrolls the form.
Photo capture — no camera buttons on desktop Mobile's "Take Photo" / "From Library" pair assumes a device camera. Desktop swaps this for a single drag-and-drop upload zone, matching the "Add Photos" pattern used on the per-project view. Thumbnail grid widened to 6 columns to use the extra space.
Time on site (D-036) One or more time blocks, each with an optional time range and an hours stepper (0.5 hr increments) plus quick-pick chips. "Add another time block" covers a return visit later the same day. "Total on site" is the single time entry — a tech does not separately re-enter these hours in the regular Odin timesheet.
Allocate hours to tasks (D-036) The tech splits the day's total across tasks worked on, in hours (not percentage). The live allocation bar shows "X of Y hrs allocated." A search box keeps this usable at 40+ tasks; in-progress tasks list first. Allocation is encouraged but not blocking.
"Other" line (D-040, renamed from Unallocated per Christine, Jun 9; D-031) A real selectable line item with its own checkbox and hours box, exactly like a task row, for work not tied to a specific task. Kept visually quiet (muted, dashed divider above) so allocating to real tasks stays the natural first choice.
Dictation mic (D-035) Browser-native speech-to-text button on the summary textarea, carried over unchanged from the mobile design.
What's intentionally not here No location field (GPS auto-captured silently), no materials-used field (possible v1.1), no weather conditions, no "submit for approval" step — admin review happens passively on the web side.
