Tasks tab notes (June 2 model: Jonas cost items + split-view detail)

  • Split-view detail panel on the right (added Pass 3). Clicking a task row opens the detail panel to the right of the cluster list, matching the Daily Logs / Assets pattern. The detail panel shows: status pill, Task ID, cluster context, title, action row (Edit, Mark Complete, Mark Blocked / Unblock, Reopen depending on state), Hours block (logged vs estimate with bar), description, key-value details (Jonas Task ID, cluster, due date, creator, linked RFI/PCN if any), and recent time entries.
  • Selected row gets a blue-soft background on the task row in the cluster list, providing clear visual anchor between the list and the detail panel.
  • Action affordances change with state. For a Blocked task (shown here): primary action is Unblock. For In Progress: Mark Complete and Mark Blocked. For Complete: Reopen. For Not Started: Mark Complete and Mark Blocked. Edit is always available.
  • Tasks in Odin are labor-tracking Jonas cost items. Per Justin's June 2 lock: only labor-tracking cost items are mirrored to Odin. Material lines, equipment, freight, permits, warranty, and contingency stay in Jonas. The PM enters the Jonas cost item number on each Odin task via the Task ID field (column shown here, mono-font, rendered as project-number-prefixed format like 9059-00301).
  • Cost items are flat (no subtasks). Per Justin's June 2 lock: Jonas cost items are flat in their accounting model, and Odin mirrors that structure. Subtask concept removed.
  • Tasks are not assigned to individuals. Per Justin's June 2 lock: tasks belong to projects. All staff (including techs not officially on the project) can see them and log time against them. The "Assigned" column has been replaced with the Task ID column.
  • Anyone can mark Complete or Blocked. Status changes are open to any staff member, not just assignees (since there are no assignees anymore).
  • Techs cannot create tasks. Tasks correspond to Jonas cost items, which are set up by the PM in Jonas at the start of a job. Techs use the existing task list and Other as the fallback when no task fits.
  • Project Estimate strip. Shows project labor budget (editable inline), sum of all task estimates ("Tasks defined"), actual hours logged, remaining hours, and variance state. In this mockup: 1,200 hr budget, 1,152 hrs defined across 18 tasks, 642 logged.
  • Variance state is color-coded. Green when tasks-defined ≤ estimate, amber 0 to 10% over, red over 10%.
  • Original Scope is one cluster showing the 15 labor cost items pulled from the Fairmont job. Header shows rollup for original scope only, independent of PCN totals.
  • All change-notice work lives in one Change Notice Scopes section rather than a separate detailed cluster per PCN. Each PCN still spawns one flat cost item (no subtasks per June 2); the three shown here are PCN-001 Penthouse Coordination (9059-00505), PCN-003 FC Bal. Valve / HW Pipe Size (9059-00506), and PCN-009 Swing Stage Outlets (9059-00509). The section header carries a combined hours rollup, styled to match Original Scope; per-PCN cost, date, and reason live in the Change Notices register and in the task detail panel, not crowding this list.
  • PCN-spawned tasks carry a PCN-XXX badge inline on the task name (the same number used when the PCN was ingested, e.g. PCN-004: Add supplemental vent), so the change-notice attribution stays visible when the list is filtered or sorted. The old Jonas "CCN" label is not surfaced to users.
  • Blocked state shows the reason inline. Level 2 Sanitary in this mockup is blocked by RFI-007. The blocking-reason banner appears in the row's name column AND in the detail panel (more prominent there with full context).
  • Est-vs-act bar per task row. Compact 7px bar showing actual hours fill against the task's estimate. Color shifts to amber if hours exceed estimate, red if blocked, green when complete and under estimate.
  • Group toggle: Cluster vs Status. Cluster grouping (default) puts Original Scope, Change Notice Scopes, and Other each in its own collapsible block. Status grouping flattens all clusters and sorts by status.

Detail panel composition

  • Header: status pill, Task ID (mono), cluster context (Original Scope or Change Notice Scopes), close-X to dismiss the panel. Below: task title, subtitle showing due date and creation context.
  • Action row: primary action button (varies by state) + Edit. Sits above the body inside a tinted band so it doesn't get lost when scrolling.
  • Blocked banner renders just below action row when status is Blocked. Red-tinted, includes the linked RFI/PCN reason and date blocked.
  • Hours section: two tiles (Logged, Estimate) plus a horizontal progress bar. Bar color matches task status (blue for in-progress, green for complete, red for blocked, etc.).
  • Description: free-text field, optional. If empty, renders as "No description set" in muted italics.
  • Details: key-value pairs for Task ID (Jonas), cluster, due date, creator, linked RFI/PCN, custom fields if any.
  • Recent time entries: last 5-10 entries logged against this task, showing tech avatar, name, date, hours, and note text from the entry. "View all" link if more than 10 entries.

Mobile behavior (per June 2 direction)

  • No mobile task detail page. Per Justin: limited info on a task aside from the name; a dedicated detail page is overkill on mobile. Controls live as inline three-dot menus on the task row in the mobile Project Tasks list. (Mockup update for the mobile inline menu is part of this Pass 3.)

What changed in this rework (June 2 outcomes)

  • Removed: Draft Tasks review inbox (techs can't create tasks), subtasks (flat cost item model), Assigned column and tr-assignees avatars (no assignment), Drafts filter chip and DRAFT status.
  • Added: Task ID column showing Jonas cost item number in mono font, populated Fairmont cost items, PCN naming convention on change-notice tasks (Jonas's internal "CCN" term is not surfaced), split-view detail panel on the right when a row is selected, Pass 3 detail panel controls (Edit, Mark Complete, Mark Blocked / Unblock, Reopen).

Out of scope for v1 (parked)

  • Gantt-style timeline view (milestones cover the schedule story; tasks stay list-based in v1)
  • Task templates / import from past projects
  • Task dependencies (Task X cannot start until Task Y is complete)
  • Resource leveling / capacity planning
  • Bidirectional Jonas API sync (Odin captures the cost item ID as a string; reconciliation happens via export, not live sync)
