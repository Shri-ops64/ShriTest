Section 7.9 · Upload Photos (confirmation)

Desktop conversionv1

Rendered as a modal, not a page This is the one screen in the set that isn't a navigation destination — mobile treats it as a full screen because that's the only pattern mobile has, but it's really a transient confirmation step triggered from an upload action elsewhere (per-project "Add Photos," the log composer's photo picker, or this Project Photos page's "Add Photos" button, shown here as the trigger). Desktop renders it as a modal over the calling page, dimmed behind it — click "Add Photos" above to see it open.
Step 1 still happens outside this mockup Step 1 is the native OS file picker (unchanged — not something we design). This modal is Step 2: review, choose destination, optionally caption, confirm.
Photo preview — fixed-size tiles, not a grid Mobile uses a 3-column grid that stretches to fill the screen width. Desktop keeps tiles a fixed 120px so the row doesn't look sparse/oversized when there are only 1–3 photos selected; tiles wrap if more are added. Remove (×) affordance unchanged.
Destination choice — the key UX moment (unchanged) Site Photos folder (default) — no log attachment. Attach to today's daily log — appears when a draft exists (or auto-creates one); photos go to both the draft and Site Photos. Default stays Site Photos per your original direction: techs need to upload without being forced through a log.
Caption — unchanged Optional, applies to the whole batch. Individual captions are edited later via the full-size photo viewer (not mocked here, same as mobile).
Footer — Cancel added alongside Upload Mobile relies on the "Cancel" link in the app bar plus a single full-width Upload button in the footer. A modal needs a clear way to back out from the bottom too, so Cancel sits as a secondary button beside the primary Upload action — otherwise unchanged, including the photo count in the button label.
