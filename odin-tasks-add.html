Add tasks screen notes

  • Why this screen exists. "+ Add task" on the Tasks tab had no destination. This is the manual path for adding tasks one or several at a time; the dev team needs a real target for that button.
  • Repeating rows, add as you go. One blank row is always present at the bottom (row 3 here). "Add another task" appends another. A single Save creates them all at once. Tested intent: comfortably handle a handful by hand; 30 to 75 from Jonas go through Import (below).
  • Minimum fields per task: Task name and Est. hours (the labour estimate that drives est-vs-act). Due date is optional. Status defaults to Not Started; Task ID (9059-004xx) is assigned automatically on save, shown in IBM Plex Mono as an ID reference.
  • Batch cluster selector. The whole batch lands in one cluster ("Add to cluster"), defaulting to Original Scope, since a Jonas import or a hand-add is usually one phase or bucket at a time. A per-row cluster override can be added in build if Thor needs to mix clusters in one go.
  • Save bar mirrors the Edit Project pattern: sticky bottom, left-offset to clear the sidebar, with a live count ("Add 2 tasks") so the PM sees exactly what they are about to create. Empty rows are ignored in the count.

Import from spreadsheet (the bulk path)

  • Primary path for long lists. The task list originates in Jonas. The recommended approach is a clean, structured Excel import: deterministic column mapping (Task name, Est. labour hours, optional cluster/due), not AI classification, so the seeded estimates can be trusted.
  • Open dependency on Thor. The Jonas export mixes materials and labour; we only want labour for tasks. Pending request to Thor (via Justin): provide a labour-only export, or include a column that flags row type (Labour vs Material). The import screen is built once that file format is confirmed. AI stays an optional convenience layer, not a thing estimate integrity depends on.
