Edit Project notes

  • Single-page sectioned form, no stepper. Edit Project assumes the user already knows what they want to change and wants to jump straight to it, not get walked through 3 steps. Different mental model than the wizard.
  • Same data model as the New Project Wizard, just rendered as a flat scrollable form with section anchor navigation on the left. Sections can be deep-linked (e.g., ?section=external-contacts) so the RFI compose flow can link directly to the contacts section when no Primary GC is set.
  • Pre-populated with realistic Fairmont Hotel project data. Empty fields would obviously be empty.

Left-rail section navigation

  • Sticky as the user scrolls. Active section auto-highlights based on scroll position; click to jump.
  • Counts on Team and External contacts. Lets the PM see at a glance how many people are on the team and how many external contacts are configured without scrolling.
  • Danger zone is visually separated with a red dot and red text on hover. Belongs in the same panel rather than a separate modal because status changes are still routine project management, not destructive operations.

Section-level status indicators

  • Each section header carries a status pill showing whether the section is properly filled. Green "All required fields filled" for sections that are healthy; amber for sections that need attention.
  • Dates & Labor budget shows "687 of 1,000 hrs logged" as the status pill. Surfaces the budget health right next to the labor estimate field, so editing the estimate is informed by current consumption.
  • Section icons match the visual language elsewhere in the app. Document icon for basics, calendar/clock for dates, people icon for team and clients, address-book icon for external contacts.

Labor budget section gets live status

  • Blue-tinted callout contains the estimate field plus a live status line: tasks defined, hours logged, hours remaining, variance vs. estimate. With link to jump to the Tasks tab.
  • Editing the estimate is informed, not blind. PM can see "I'm at 687 of 1,000 already, should I bump this to 1,100?" instead of guessing.

External contacts section

  • Same repeating-card pattern as in the wizard step 3. Primary GC card has blue-tinted background and amber star treatment.
  • This is where most external contacts get added in practice. The wizard step 3 is skip-able, so the typical flow is: wizard runs, project gets created without contacts, RFI compose flow tries to auto-suggest and finds nothing, PM gets prompted to come fill in contacts here. Edit Project is the workhorse surface for this data.
  • Section can be deep-linked. The RFI compose panel's empty contacts state will link directly here.

Project Actions (the three-tier confirmation pattern)

  • Renamed from "Danger zone" per Mike's May 28 feedback. Most of these are routine status transitions, not destructive operations; "Danger zone" was the wrong frame and diluted the warning when you got to the one that actually was destructive.
  • Three tiers of confirmation matching three levels of consequence:
    Tier 1 (Mark On Hold): no confirm dialog. Click applies immediately and surfaces an Undo toast for 10 seconds. Right pattern for genuinely reversible, low-stakes actions.
    Tier 2 (Mark Complete): simple "Are you sure?" confirm dialog. Two buttons (Cancel, Mark Complete). Dialog explains that completion is reversible from the Project List view. No typed confirmation; the dialog itself is enough friction.
    Tier 3 (Cancel Project): typed-confirmation modal. User must type the project name in ALL CAPS to enable the confirm button. Modal explains exactly what cancellation means and steers PMs toward Mark Complete instead for any project that had real work done.
  • The typed-confirmation pattern is reserved for the destructive action only. If we required typed confirmation on every action, PMs would train themselves to type past warnings on routine status changes, which defeats the purpose. Keeping the typed confirm narrow keeps it meaningful.
  • Visual hierarchy reinforces the tiers. Tier 1 and 2 cards have standard grey borders and white-with-grey-border action buttons. Tier 3 card has a soft red border, red-tinted background, and a soft-red action button. The status pill in the section header shows "Status: Active" so PMs see what they're acting on.
  • Status changes emit Activity events (PROJECT_STATUS_CHANGED) and surface in the project's Activity tab and the Overview tab's status pill.
  • The Cancel typed-confirmation modal is mocked as a separate state below the Project Actions section, showing the typed input in a valid (matching) state with the green checkmark status line. In production this appears as an overlay modal on click.
  • Delete is not supported in v1. Cancelled or Completed projects stay in the database with their full history. Per Justin's reporting needs.

Public/Private cut from the wizard and Edit Project

  • Removed entirely per Mike's May 28 confirmation. Per Justin's open-access culture, all Thor projects are public. The toggle was paying rent for a case that almost never happens.
  • Database can retain a visibility column for future flexibility; UI doesn't expose it in v1. If Thor ever needs project-level privacy (acquisition project, sensitive client, internal R&D), that's a v2 addition.

Sticky save bar at bottom

  • Always visible while scrolling. Shows unsaved-state indicator plus the timestamp of the last save. Bumped above the page fold via sticky positioning so the PM doesn't have to scroll to find Save.
  • One save commits all sections. No per-section save buttons. Reduces cognitive load and prevents the "did I save?" anxiety.
  • "Discard changes" reverts to last-saved state. No partial revert per section in v1.

Out of scope

  • Per-field change tracking ("Bob changed start date from May 1 to May 8 on Tuesday")
  • Permissioned section editing (e.g., only PMs can edit Team)
  • Project template cloning ("Create new project based on this one")
  • Project archiving as separate from Cancel/Complete
