Section 6.6.3 · Raise RFI

Desktop conversionv1

Converted from mobile mockup Built from the mobile Raise RFI composer, adapted to the established desktop chrome and the same form + sticky summary rail pattern used for the Daily Tech Log Composer and Submit Time conversions.
Five fields only (unchanged) Matches the lean intake spec: photos, subject, description, linked task. Number and date auto-populate on submit — not asked. No recipient, due date, priority, discipline, drawing reference, spec section, or blocking-task toggle. Field user captures; PM handles the rest.
Shared by all field roles (D-038) Same composer for Technicians, Foremen, and Supervisors — only created_by_role differs on the record, the form is identical.
Photo capture — dropzone replaces Camera/Gallery Mobile leads with two big buttons (Camera primary, Gallery secondary) because "look at this" is the most common way these start, and there's no keyboard-first alternative on a phone. Desktop swaps this for the same drag-and-drop upload zone used on the Daily Tech Log Composer and this project's other conversions — no camera affordance needed. Thumbnail grid widened to 6 columns.
Intro card sets expectation (unchanged) "Submit posts this RFI to the project. The PM takes it from there and emails the GC. There is no approval step." Removes the anxiety of "am I sending this to the GC directly," without implying a gate that doesn't exist.
Stage pill (unchanged) "Internal capture" in the header reinforces this is the casual capture step, not the formal outbound send. Moved from the app bar (mobile) into the page header, next to the title, matching the composer conversions' header pattern.
Subject & Description hints (unchanged) Subject: "one line" hint + "Short. What's the question in five to ten words." Description: "In your own words. The PM will rewrite this for the GC if needed." Both keep the field user from overthinking phrasing. 500-char counter on description carried over.
Linked task — optional (unchanged) "Skip if not sure" helper text. Opens the same project-task picker pattern used elsewhere. Pre-fills the PM's mental model of what this might block.
Sticky rail replaces the mobile footer Mobile pins Cancel/Submit RFI to a two-column footer bar. Desktop moves these into the sticky right rail, with a running RFI summary (project, subject, linked task, photo count) above them — consistent with the other composer conversions.
What happens on Submit (unchanged) Record created as OPEN (D-038, no approval gate, no Draft state) — posts straight to the project's Change Notices register. Confirmation toast, then return to the per-project view. PM handles the outbound GC email from their own client and later captures the response back into the desktop RFI detail. RFI_CREATED activity event fires with created_by_role.
What field roles still do NOT do (unchanged) No PCN creation (inbound GC documents only — forward the email to the PM instead). No compose-and-send to the GC. No answering RFIs — the PM captures the GC's response on desktop.
