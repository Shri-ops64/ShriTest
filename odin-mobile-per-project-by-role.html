Mobile per-project view by role (v1)

  • Role-based affordance visibility. Each role sees only the actions they're meant to perform. Keeps each role's home screen focused.
  • Tech: one full-width primary, Write Daily Tech Log, plus Raise RFI (secondary). Submit Time was removed for techs (D-040): time is captured inside the Daily Tech Log, so a separate Submit Time would be a redundant second entry for the same hours.
  • Foreman: Submit Time + Foreman Report (two tiles) + Raise RFI. Submit Time is a real time entry here (time blocks + hours-to-task allocation, same as the log), because foremen file a weekly report rather than a Daily Tech Log but still bill project hours. The Foreman Report card shows "weekly · due Friday".
  • Supervisor: Submit Time + Supervisor Report (two tiles) + Raise RFI. Same reasoning: supervisors are Thor employees billing hours on the projects they audit, with no daily log, so Submit Time is their standalone time entry.
  • Recent project activity stays the same shape across all roles. The activity is project-scoped, not role-scoped; everyone sees what happened on the project regardless of role. Per the "everyone sees everything" v1 visibility decision.
  • Role pill in the app bar. Small "Tech / Foreman / Supervisor" indicator in the top-right of the app bar. Mostly for the v1 demo so it's obvious which role we're showing. Could be removed in production or kept as a quiet signal.

Action color coding

  • Submit Time stays green gradient (existing pattern, ties to TimeTracker).
  • Daily Tech Log stays pink-red gradient (existing pattern).
  • Foreman Report uses purple gradient. Distinct from Daily Tech Log so foremen don't confuse the two when scanning.
  • Supervisor Report uses amber gradient. Matches the "audit / oversight" feel and the badge color used elsewhere.
  • Raise RFI stays blue (existing pattern, RFI module convention).

Out of scope / TBD

  • Multi-role users (PM who is also occasionally a Foreman, etc.). v1 assumes one primary role per user. v2 may need role-switching UI.
  • Push notifications reminding the foreman to submit on Friday. Useful but not in v1.
  • "Save as draft" for partially-completed reports across sessions. Drafts are in the v1 design; cross-device draft sync is v2.
