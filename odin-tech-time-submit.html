Submit Timesheet (Project context) notes

  • This is the existing production Submit Timesheet form (image 3 from the uploads), with two changes for the project-context variant.

What's different from the service version

  • "Work Order" field becomes "Project": same field slot, different label, different picker source. When work type = Projects, the field shows projects instead of work orders.
  • Project is pre-filled when the tech entered this form from the per-project view's "Submit Time" button. Read-only in that case (greyed out, locked). The tech wants to log to THIS project; switching is a back-out gesture.
  • New optional "Task" field: lists the tech's open tasks on the selected project. Lets them attribute time to a specific task. Optional because techs may not always work on a specific task (general project labor).

What's the same

  • Timesheet Type (Billable / Non-Billable) radio
  • Date picker (today by default)
  • Work Performed text
  • Arrival / Departure time pickers
  • Enter your time hours/minutes display
  • Overtime button
  • Supplier Receipts section
  • Pink-red gradient Save button

If the tech came via the universal path (Home → Submit a timesheet)

  • They first see the existing TimeTracker work-type picker (image 2 from uploads: Emergency Service / Maintenance / Projects / Non-Billable).
  • If they pick Projects, the form opens with this layout but the Project field is empty (not pre-filled). Tapping it opens the project picker (the picker mockup we built earlier) with assigned projects at top.
