Section 7.3 · Per-project tech view

Tech project view — desktopv3

Corrected vs. v2 — spec audit The v2 missed several things flagged by direct read of spec section 7.3 + D-036 + D-040: single primary action (was two), Raise RFI as secondary (was co-equal primary), no KPIs in header (was four stat blocks), prominent Add Photos button (was missing), 8 photos in grid (was 5+1).
Action structure — single primary Per D-040: techs do not get a separate Submit Time button on the per-project view. Time entry is captured inside the Daily Tech Log composer. So this view shows one full-width primary (Write Daily Tech Log, pink-red gradient), with Raise RFI as a secondary card below (lighter visual weight — white card, blue-tinted icon, smaller padding). Spec lines 1248, 1284, and 1350 are all consistent on this.
Compact header — no KPIs Spec line 1086 is explicit: "What's intentionally NOT on this view: team list, project KPIs, hours-to-date, milestones, change notices register, assets folder browser, client reports." The header carries identification only — status pill, ID pill, name, location, client. KPIs and milestones live on the admin Overview tab; if a tech needs them, that's one tab strip click away.
Add Photos — prominent at top of Photos card Per spec line 1082: "prominent 'Add Photos' button at the top." It's a standalone upload affordance for when a tech took photos but didn't write a log (or wants to add photos to Site Photos folder without going through a log). Styled as a dashed-border dropzone-style button — desktop affords drag & drop, so the button hints at that.
8 photos in the grid Spec specifies "photo grid (8 most recent)." Laid out as 4×2 on desktop with the 8th tile showing the overflow count.
Stale spec language flagged Section 7.3 lines 1080 and 1084 still describe Logs and Photos as "scoped to this tech" (the old "my" framing). That's stale — D-030 dropped the "my" concept and D-026 made everything open access. Same drift as section 7.4. The design here uses project-scoped framing; the spec language needs a rewrite. Same pattern as the section 7.4 / section 8.1 follow-up.
Activity feed — multi-tech visible Per D-026, all activity visible — tech logs from Jamie Chen and Dev Mehta show up alongside Shrikant's. PCN-004 approval shows the $8,200 cost impact (no information hiding). RFI-007 answer shows the resolution and back-reference to PCN-003. Event-type dots match the color model from spec section 7.3 line 1076 (logs amber, tasks green/blue, milestones grey, PCNs blue, RFIs purple).
Foreman / Supervisor variants — not shown here Per spec line 1350: Foreman or Supervisor role on this project gets a Submit Time card plus their report composer card, layered on top of the base tech view. Worth designing as a separate variant once this base is signed off.
